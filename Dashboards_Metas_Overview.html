Relatórios otimizados para mobile

Usuários de dispositivos móveis podem visualizar qualquer página de relatório do Power BI nos aplicativos móveis. No entanto, relatórios projetados para uso em um computador podem ser difíceis de ler e interagir em telas de celular. Para resolver isso, o Power BI permite criar layouts mobile adicionais para as páginas de um relatório, otimizados especificamente para telas pequenas.

Quando existe um layout mobile para uma página, ele é exibido automaticamente sempre que o dispositivo está na orientação retrato. Se o usuário girar o telefone para o lado (paisagem), o Power BI mostra a versão normal (não otimizada) do relatório, igual à do computador.

Nos aplicativos móveis, os relatórios que possuem páginas otimizadas para celular exibem um ícone especial indicando essa disponibilidade.

Os layouts mobile só aparecem quando o relatório é aberto pelos aplicativos móveis do Power BI (iOS e Android). Em um navegador web, o relatório sempre é exibido no layout padrão, mesmo em um celular.

Recursos para criar relatórios mobile

O Power BI oferece um conjunto de recursos dedicados à criação de versões otimizadas para celular:

Modo de exibição em layout mobile

Um editor dedicado no qual você cria o layout mobile automaticamente ou arrastando e soltando visuais em um canvas interativo que emula um telefone.

Criação automática

A opção de auto-criação gera um layout mobile inicial a partir do relatório existente, que pode ser usado como está ou ajustado depois.

Painel de formatação

Permite ajustar com precisão as configurações de formato de cada visual especificamente para a versão mobile.

Visuais e slicers adaptáveis

Diversos visuais e segmentações de dados podem ser otimizados para funcionar bem em telas pequenas.

Com esses recursos, você pode selecionar, reorganizar e reformatar apenas os visuais relevantes para o público mobile, criando páginas atraentes, focadas e fáceis de usar em celulares.

Se você criar o layout mobile no Power BI Desktop, basta publicar o relatório principal do Desktop para o serviço Power BI — a versão mobile é publicada junto automaticamente. Se o layout mobile for criado diretamente no serviço Power BI, basta salvar o relatório.

O modo de exibição em layout mobile

O modo de layout mobile está disponível tanto no Power BI Desktop quanto no serviço Power BI. Para abri-lo, use o alternador de layout na parte inferior da página ou selecione a faixa de opções Exibir e escolha Layout mobile.

Esse modo de exibição reúne os seguintes componentes:

ComponenteFunção
Canvas de layout mobileÁrea interativa com grade fina para posicionar os visuais; possui controles para ligar/desligar a grade, o encaixe automático (snap-to-grid) e travar visuais no lugar.
Painel de visuais da páginaLista todos os visuais (visíveis e ocultos) da página original do relatório, para arrastar até o canvas mobile.
Painel de visualizaçõesMostra as configurações de formato do visual selecionado no canvas, permitindo estilizá-lo para a versão mobile.
Painel de seleçãoPermite alterar a ordem de camadas (layering) dos visuais no canvas.
Opção de criação automáticaGera um layout mobile completo a partir dos visuais do relatório, servindo como ponto de partida.

O canvas é interativo, permitindo testar o comportamento de botões, slicers e visuais antes mesmo de publicar o relatório — embora algumas limitações se apliquem (por exemplo, tooltips ficam desabilitados no canvas de edição, mas funcionam normalmente no aplicativo móvel publicado).

O que afeta a qualidade da criação automática? ▸
  • O mecanismo lê o relatório da esquerda para a direita, de cima para baixo — layouts com forte componente vertical (como um menu de navegação lateral) tendem a ficar piores.
  • Imagens de fundo (background) não são suportadas pelo mecanismo de criação automática.
  • Excesso de sobreposição de visuais é um desafio; o resultado pode não ser ideal.
  • Se houver muitos visuais (incluindo ocultos), nem todos cabem no canvas — os que sobrarem continuam listados no painel de visuais da página.
  • Seleções de slicers feitas no canvas mobile não são preservadas ao alternar para o layout web, e vice-versa; ao publicar, prevalecem as seleções definidas no layout web.

Como criar um layout mobile

Para montar o layout mobile, o essencial é:

  1. Abrir o modo de layout mobile no relatório desejado.
  2. Usar Criação automática para gerar um ponto de partida (pode ser desfeito com Ctrl+Z se o resultado não agradar) ou montar manualmente.
  3. Arrastar visuais do painel de visuais da página para o canvas — ao soltar, eles se encaixam na grade automaticamente.
  4. Redimensionar cada visual selecionando-o e arrastando as alças nos cantos (mantenha Shift pressionado para preservar a proporção).
  5. Ajustar a ordem de camadas pelo painel de seleção, já que cada novo visual é adicionado acima dos demais.
  6. Remover visuais indesejados clicando no X no canto do visual ou selecionando-o e pressionando Delete; o botão de borracha no painel remove todos de uma vez.
Remover um visual do canvas mobile não o exclui do relatório: ele continua disponível no painel de visuais da página e o layout original (desktop) permanece inalterado. É possível também arrastar visuais ocultos para o canvas — eles só aparecerão quando sua visibilidade mudar no relatório principal (útil para cenários com bookmarks).

Otimizando a formatação dos visuais para mobile

O painel de visualizações permite ajustar com precisão o formato de cada visual no layout mobile. Ao selecionar um visual pela primeira vez, suas configurações herdam os valores do layout desktop — mas assim que você altera qualquer configuração, ela se desconecta do desktop e passa a valer apenas para a versão mobile (um ícone indica que a configuração foi alterada). É possível reverter as mudanças por categoria (opção Clear mobile changes) ou para o visual inteiro (menu Clear mobile formatting).

Configurações de tamanho e posição nunca são herdadas do layout desktop, portanto nunca exibem indicador de alteração — elas são sempre específicas do mobile.

Alguns ajustes de formatação particularmente úteis para telas pequenas:

  • Orientação da grade: elementos empilhados verticalmente no desktop (como um navegador de páginas) costumam funcionar melhor na horizontal em telas de celular.
  • Forma dos elementos: uma forma usada no desktop (por exemplo, um retângulo de fundo) pode ser convertida em outra forma (como uma linha) para servir de elemento decorativo no mobile.
  • Tamanho da fonte: fontes do layout desktop costumam ser grandes demais para o mobile; reduzi-las (e ajustar a unidade de exibição, como de milhares para milhões) ajuda o texto a caber melhor.
  • Tamanho e posição: além da grade fina e das guias inteligentes do canvas, é possível definir valores exatos de tamanho e posição, inclusive selecionando vários visuais ao mesmo tempo.
  • Economia de espaço: desativar legendas e eixos e ativar rótulos de dados centralizados pode manter a clareza de um gráfico usando menos espaço vertical.
Visuais responsivos e slicers no mobile ▸

Muitos visuais, especialmente gráficos, são responsivos por padrão: eles se adaptam dinamicamente ao tamanho disponível, priorizando os dados (por exemplo, removendo espaçamento ou movendo a legenda para o topo conforme o visual encolhe). Se a responsividade atrapalhar sua formatação manual, desative-a em Geral > Propriedades > Opções avançadas > Responsivo.

Slicers também podem ser configurados para mobile: você decide se permitem seleção única ou múltipla, e se são verticais, horizontais ou responsivos (slicers responsivos precisam ser horizontais). Um slicer responsivo mostra mais ou menos opções conforme seu tamanho, podendo virar apenas um ícone de filtro quando muito pequeno.

Reorganizando a camada (layering) dos visuais

Depois de posicionar os visuais no canvas, use o painel de seleção para ajustar a ordem de sobreposição, se necessário:

  • O painel lista todos os visuais do canvas: o primeiro da lista fica na camada mais acima, o último na camada mais abaixo.
  • Para reordenar, arraste e solte um item na lista ou use os botões de seta para movê-lo para cima ou para baixo.
  • O painel também mostra o status de visibilidade de cada visual, mas essa visibilidade só pode ser alterada no layout desktop (não no modo mobile).

Boas práticas para layouts mobile

Planeje desktop e mobile juntos ▸

Construa os layouts desktop e mobile de cada página em conjunto, para manter coerência entre eles. Ao duplicar uma página que já tem os dois layouts, ambos são duplicados — por isso, vale criar uma página "modelo" com elementos recorrentes (cabeçalho, navegador de páginas) e usá-la como base para as demais páginas do relatório.

Foque no conteúdo essencial ▸
  • Inclua apenas os visuais mais significativos e usados com frequência.
  • Reduza o tamanho da fonte dos títulos (nunca abaixo de 9 pontos).
  • Remova detalhes pouco relevantes, como títulos de eixo, linhas de grade e legendas, sempre que possível.
  • Posicione navegadores de página e slicers na horizontal, em vez de na vertical.
Espace bem os elementos ▸

Evite espaços em branco desnecessários dentro de cada visual, mas mantenha ao menos 6 a 8 pontos de espaçamento entre elementos (tanto na vertical quanto na horizontal). Considere expandir os visuais até a largura máxima da tela (323 pontos), lembrando que uma margem padrão já é aplicada automaticamente. Evite colocar visuais lado a lado, exceto visuais de elemento único (cartões, KPIs) ou não relacionados a dados (botões).

Organize os visuais como uma narrativa ▸

O fluxo do layout mobile é de cima para baixo. Posicione os visuais mais importantes no topo da página, agrupe visuais relacionados em sequência e deixe os menos relevantes mais abaixo (acessíveis por rolagem) ou simplesmente fora do layout mobile. Menos visuais significa carregamento mais rápido e melhor desempenho.

Evite barras de rolagem internas ▸

Defina a altura de cada visual de forma que todos os seus elementos internos fiquem visíveis, sem cortes — isso evita uma barra de rolagem dentro do próprio visual, além da barra de rolagem da página. Lembre-se de que dispositivos móveis variam de altura.

Comece pela criação automática ▸

Use a opção de criação automática de layout mobile como ponto de partida: ela posiciona os visuais do relatório no canvas tentando preservar a funcionalidade do layout desktop. A partir daí, refine o resultado com as opções de formatação do modo mobile.

Tamanhos mínimos recomendados por tipo de visual

A tabela a seguir resume as categorias de tamanho mínimo recomendado (a largura máxima da tela no canvas mobile é 323 pt):

CategoriaTamanho mínimoExemplos de visuais

L323 x 180 ptGráficos de barras, colunas, linhas, área, pizza, rosca, funil, dispersão, cascata, Q&A, treemap, ribbon

Introdução a dashboards e tiles

O que é um dashboard

Um dashboard do Power BI é uma única página — muitas vezes chamada de canvas — que conta uma história por meio de visualizações. Por estar limitado a uma única página, um dashboard bem projetado traz apenas os destaques dessa história; os detalhes ficam nos relatórios relacionados.

Dashboards são um recurso do serviço Power BI e não existem no Power BI Desktop. Você não pode criar dashboards em dispositivos móveis, mas pode visualizá-los e compartilhá-los por lá.

As visualizações que aparecem em um dashboard são chamadas de tiles (blocos). Você fixa (pin) tiles em um dashboard a partir de relatórios, e cada relatório é baseado em um modelo semântico. Assim, um dashboard funciona como uma porta de entrada para os relatórios e modelos semânticos subjacentes: selecionar uma visualização leva você até o relatório e o modelo que a originaram.

Dashboard x relatório: principais diferenças

Dashboards e relatórios parecem semelhantes — ambos são telas cheias de visualizações —, mas há diferenças importantes:

CapacidadeDashboardsRelatórios

FiltragemNão é possível filtrar/segmentar o dashboard (é possível filtrar um tile em modo foco, sem salvar)Sim, com várias formas de filtrar, destacar e segmentar

É necessária uma licença Power BI Pro ou Premium Per User (PPU) para criar dashboards em workspaces compartilhados. Em Meu workspace, é possível criar dashboards sem essas licenças.

Vantagens dos dashboards

Dashboards são uma forma de monitorar o negócio e ver as métricas mais importantes de relance. As visualizações podem vir de um único modelo semântico ou de vários, e de um único relatório ou de vários — combinando dados locais (on-premises) e na nuvem em uma visão consolidada.

Um dashboard não é apenas uma imagem estática: ele é altamente interativo, e os tiles são atualizados conforme os dados subjacentes mudam.

A capacidade de criar um dashboard é considerada um recurso de "criador" (creator) e exige permissão de edição sobre o relatório de origem. Colegas com quem um relatório foi apenas compartilhado (ou que o acessam via um app do Power BI) normalmente têm apenas permissão de consumo e não conseguem fixar tiles.

O que é um tile

Um tile é um instantâneo (snapshot) dos seus dados, fixado no dashboard. É possível criar tiles a partir de relatórios, de outros dashboards, da caixa de perguntas do Q&A, do Excel, de relatórios paginados do SQL Server Reporting Services (SSRS) e mais. Além de fixar tiles existentes, você pode criar tiles independentes diretamente no dashboard usando o controle Add tile — como caixas de texto, imagens, vídeos, dados em streaming e conteúdo web.

OrigemComo o tile chega ao dashboard
RelatórioFixando um visual ou uma página inteira
Outro dashboardFixando um tile já existente
Excel (OneDrive corporativo)Fixando um intervalo de células, tabela ou planilha inteira
Q&AFixando a visualização gerada por uma pergunta em linguagem natural
SSRS / Power BI Report ServerFixando itens de relatórios paginados locais
Add tile (direto no dashboard)Criando tiles autônomos de imagem, vídeo, texto, streaming ou web

Interagindo com tiles

  • Mover e redimensionar: arraste o tile pelo dashboard; passe o cursor sobre ele e use a alça de redimensionamento.
  • Menu de ações: passe o mouse sobre o tile e selecione as reticências (...) para adicionar comentários, abrir o relatório de origem, ver em modo foco, exportar os dados, editar título/subtítulo e hyperlink, executar insights, fixar o tile em outro dashboard ou excluí-lo.
  • Selecionar um tile normalmente leva você ao relatório, workbook do Excel Online, relatório SSRS ou pergunta do Q&A que o originou (ou a um link personalizado, se definido).
Se a visualização original usada para criar o tile mudar (por exemplo, um gráfico de linhas alterado para gráfico de barras no relatório), o tile fixado no dashboard não muda de tipo — apenas os dados são atualizados. Algumas alterações visuais (cor de fundo, largura/altura, tooltips) também não se refletem no tile.

Criando um dashboard a partir de um relatório

A forma mais simples de começar é fixar visualizações de um relatório existente. O fluxo essencial é:

  1. Abra o relatório em modo de edição.
  2. Passe o cursor sobre a visualização que deseja fixar e selecione o ícone de pin.
  3. Escolha fixar em um dashboard existente (selecionando-o na lista) ou em um novo dashboard (informando um nome).
  4. Selecione Fixar (Pin). O Power BI cria o dashboard no workspace atual e exibe uma mensagem de sucesso; selecione Ir para o dashboard para conferir o tile recém-criado.
  5. Repita o processo para fixar mais visualizações no mesmo dashboard, escolhendo "dashboard existente" nas próximas vezes.
É possível fixar uma página de relatório inteira de uma só vez (pin de página inteira). Nesse caso os tiles resultantes são "ao vivo" (live): você pode interagir diretamente com eles no dashboard, e alterações feitas depois no relatório (novos filtros, campos) se refletem no tile automaticamente.

Limitações ao fixar visuais em dashboards

Formatação que se perde ao fixar ▸
  • Borda, sombra e configurações de fundo, além da formatação de título/subtítulo (exceto o próprio texto), são ignoradas no tile.
  • Cartões (card visuals) exibem o valor sempre na fonte "DIN" em texto preto (a cor pode ser trocada por meio de um tema de dashboard personalizado).
  • Formatação condicional não é aplicada.
  • Fontes personalizadas fora da lista suportada pelo Power BI não são aplicadas.
Interatividade que se perde ao fixar ▸
  • Se você fixar apenas um visual (não a página inteira), filtros e slicers do relatório podem não persistir da mesma forma no tile.
  • Botões que acionam bookmarks ou aplicam/limpam filtros não têm efeito em um tile de dashboard — essas ações só fazem sentido dentro do contexto de um relatório.
  • Como visualizador (não criador) do dashboard, geralmente não é possível mover ou redimensionar tiles.
  • Nem todos os visuais personalizados, slicers específicos ou tipos não suportados podem ser fixados; imagens de fundo muito grandes também podem impedir a fixação.

Criando uma cópia de um dashboard

Duplicar um dashboard é útil para testar mudanças sem afetar o original, distribuir versões por colega/região/equipe, ou reaproveitar um layout com uma nova fonte de dados de estrutura semelhante. Apenas o criador do dashboard pode duplicá-lo; dashboards recebidos como parte de um app não podem ser duplicados.

  1. Abra o dashboard que deseja copiar.
  2. Selecione Arquivo > Salvar uma cópia.
  3. Dê um nome à cópia e selecione Duplicar.
  4. O novo dashboard é salvo no mesmo workspace do original.
  5. Abra a cópia e edite conforme necessário: mova, renomeie ou redimensione tiles; edite hyperlinks; adicione novos tiles a partir do menu do dashboard, de Q&A ou de relatórios; ajuste configurações em Arquivo > Configurações (nome, Q&A ativado/desativado, fluxo dos tiles).

Fixar conteúdo em dashboards

Além de fixar visuais diretamente de um relatório, o Power BI oferece diversas outras formas de adicionar tiles a um dashboard: copiando de outro dashboard, a partir de uma pasta de trabalho do Excel, a partir de um resultado do Q&A, ou fixando uma página de relatório inteira como um tile único e interativo.

Pré-requisitos comuns a essas operações: uma licença Fabric gratuita é suficiente para editar dashboards em Meu workspace; para editar dashboards em outros workspaces é necessária uma licença Power BI Pro e, no mínimo, o papel de Colaborador (Contributor) nesse workspace.

Fixar um tile de um dashboard para outro

Uma forma de adicionar um tile a um dashboard é copiá-lo de outro dashboard já existente. Ao selecionar esse tile depois, ele continua vinculado ao local original onde foi criado (um relatório ou o Q&A).

  1. Abra o dashboard que contém o tile desejado.
  2. Passe o cursor sobre o tile, selecione Mais opções (...) e escolha Pin tile.
  3. Escolha fixar em um dashboard existente (selecionando-o na lista) ou em um novo dashboard (informando o nome).
  4. Selecione Fixar. Se o dashboard de destino ainda não tiver um rótulo de confidencialidade, o Power BI solicitará que você defina um.
  5. Uma mensagem de sucesso confirma a operação; selecione Ir para o dashboard para ver, renomear, redimensionar, vincular e mover o tile fixado.
Não é possível fixar tiles de dashboards que foram apenas compartilhados com você (sem permissão de edição).

Fixar um tile a partir do Excel

Antes de fixar um tile de uma pasta de trabalho do Excel, é preciso conectar esse arquivo ao serviço Power BI. A conexão traz uma versão vinculada e somente leitura do workbook para o Power BI, permitindo fixar intervalos, tabelas, PivotTables, gráficos e até planilhas inteiras em dashboards.

Conectar o workbook

  1. Faça upload do arquivo Excel para o seu OneDrive corporativo (for work or school).
  2. No Power BI, vá até Meu workspace, selecione Carregar > OneDrive – Business e navegue até o local do arquivo.
  3. Selecione o arquivo e escolha Carregar. O workbook passa a aparecer no workspace, identificado por um ícone de Excel.
  4. Abra o workbook no Power BI selecionando seu nome.
Alterações feitas no workbook dentro do Power BI não são salvas e não afetam o arquivo original no OneDrive. Para editar de fato, use Editar no canto superior direito, que abre o arquivo no Excel Online ou no Excel desktop — essas mudanças podem levar alguns minutos para se refletir nos tiles já fixados.

Fixar um intervalo, tabela ou planilha inteira

  1. Selecione as células que deseja fixar (para uma tabela, inclua os cabeçalhos; para uma PivotTable, inclua todas as partes visíveis, inclusive filtros).
  2. Selecione o ícone de pin.
  3. Escolha um dashboard existente ou informe o nome de um novo.
  4. Selecione Fixar. Uma mensagem de sucesso confirma a criação do tile.

Um tile criado a partir de uma tabela ou PivotTable exibe a tabela inteira; se linhas ou colunas forem adicionadas, removidas ou filtradas no workbook original, o tile reflete essas mudanças. Selecionar o tile abre o workbook vinculado no Power BI (é necessária permissão de leitura sobre o arquivo).

O Power BI usa o Excel Services para recuperar os dados dos workbooks. Por isso, alguns recursos do Excel não têm suporte nos tiles — por exemplo, sparklines, formatação condicional com conjunto de ícones e segmentações de tempo (time slicers).

Fixar um tile a partir do Q&A

O Q&A é a ferramenta do Power BI para explorar dados usando linguagem natural: você faz uma pergunta e recebe a resposta em forma de visualização, que pode então ser fixada em um dashboard.

As experiências de Q&A serão descontinuadas em dezembro de 2026. A recomendação é migrar para o Copilot do Power BI, que oferece uma forma mais avançada e integrada de consultar dados em linguagem natural.
  1. Abra um dashboard que já tenha ao menos um tile fixado a partir de um relatório (o Q&A busca respostas nos modelos semânticos associados aos tiles daquele dashboard).
  2. Na caixa de perguntas no topo do dashboard, comece a digitar o que deseja saber sobre os dados.
  3. Selecione uma das sugestões apresentadas ou pressione Enter.
  4. Selecione Pin visual no canto superior direito para adicionar o gráfico gerado ao dashboard.
  5. Escolha um dashboard existente (dentro do workspace atual) ou informe o nome de um novo.
  6. Selecione Fixar. Uma mensagem de sucesso confirma a criação do tile; selecione Ir para o dashboard para renomear, redimensionar, adicionar hyperlink e reposicionar o tile.
Como o Q&A escolhe os modelos semânticos? O Q&A tem acesso a todos os modelos semânticos que possuem ao menos uma visualização fixada no dashboard atual (o dashboard listado no painel de navegação superior).

Se a caixa de perguntas não aparecer no dashboard, verifique com o administrador do Power BI — é possível desativar o Q&A em nível administrativo.

Fixar uma página de relatório inteira como tile ao vivo

Outra forma de adicionar um tile é fixar uma página de relatório inteira de uma só vez. Esse método permite levar várias visualizações para o dashboard em uma única ação, e os tiles resultantes são ao vivo (live): você pode interagir com eles diretamente no dashboard, e qualquer alteração feita depois no editor do relatório (novo filtro, mudança de campos) é refletida no tile.

Fixar páginas inteiras como tiles ao vivo só está disponível no serviço Power BI (app.powerbi.com), não é possível pelo Power BI Desktop nem pelos aplicativos móveis.
  1. Abra o relatório no serviço Power BI e navegue até a página que deseja fixar.
  2. Sem nenhuma visualização selecionada, abra o menu Mais opções (...) no canto superior direito do relatório e escolha Pin to a dashboard.
  3. Na caixa de diálogo, escolha um dashboard existente ou informe o nome de um novo. A opção Pin live page garante que alterações futuras no relatório apareçam no tile quando a página for atualizada.
  4. Selecione Pin live. Uma mensagem de sucesso confirma que a página foi adicionada como tile.
  5. Abra o dashboard para ver o tile: é possível renomear, redimensionar, vincular e mover a página fixada, além de interagir com ela — por exemplo, selecionar uma barra em um gráfico de colunas para cruzar filtros (cross-filter) e destacar (cross-highlight) as demais visualizações dentro do próprio tile.
Não é possível fixar tiles de relatórios que foram apenas compartilhados com você, nem de relatórios em que você tem somente acesso de visualização — é necessária permissão de edição. Além disso, tiles de página de relatório não são interativos quando visualizados nos aplicativos móveis do Power BI.

Alertas e conteúdo rico em dashboards

Alertas de dados no serviço Power BI

Os alertas de dados avisam você quando o valor de um tile de dashboard ultrapassa um limite definido por você. Eles são pessoais: só quem cria o alerta consegue vê-lo, mesmo que o dashboard seja compartilhado com outras pessoas — o dono do dashboard não enxerga os alertas configurados por quem apenas visualiza.

Onde funciona: alertas podem ser criados em tiles do Meu Workspace, em dashboards compartilhados que estejam em uma capacidade Premium, ou (com uma licença Power BI Pro) em qualquer outro workspace. Eles ficam sincronizados entre o serviço Power BI e os aplicativos móveis, mas não existem no Power BI Desktop.

Requisitos e limitações dos alertas

  • Só podem ser configurados em tiles fixados a partir de visuais de relatório — apenas gráficos de indicador (gauge), KPIs e cartões.
  • Funcionam também em visuais de conjuntos de dados de streaming, desde que o visual (KPI, cartão ou gauge) tenha sido fixado a partir de um relatório. Tiles de streaming criados diretamente no dashboard (via Adicionar tile > Dados de streaming personalizados) não suportam alertas.
  • Só funcionam com tipos de dados numéricos; não há suporte para cartões com medidas de data ou hora.
  • Só disparam quando os dados são atualizados — não funcionam sobre dados estáticos, e você não recebe alertas duplicados para um valor que não mudou.
  • É possível criar até 250 alertas no total, entre todos os seus modelos.
  • Não há suporte a co-propriedade: para transferir um alerta entre usuários é preciso recriá-lo (e recriar também qualquer fluxo do Power Automate associado).
Alertas por dados sensíveis chegam até você por notificação e, opcionalmente, e-mail. Se o dispositivo móvel usado para ver esses alertas for perdido ou roubado, recomenda-se desativar todas as regras de alerta pelo serviço Power BI.

Como criar um alerta em um tile

  1. No dashboard, passe o mouse sobre o tile desejado e selecione as reticências (...).
  2. Selecione Gerenciar alertas.
  3. Clique em + Adicionar regra de alerta, mantenha o controle Ativo ligado e dê um título ao alerta.
  4. Defina a condição (por exemplo, "acima de 100") e a frequência de verificação (a cada hora ou uma vez por dia).
  5. Marque a caixa de e-mail se quiser também receber a notificação por e-mail, além da central de notificações.
  6. Selecione Salvar e fechar.

Quando o dado atualizado cruza o limite configurado, o Power BI verifica quanto tempo passou desde o último alerta enviado; se o intervalo (1 hora ou 24 horas) já passou, um novo alerta é disparado, com link direto para o tile correspondente.

Gerenciando e removendo alertas

Existem três formas de gerenciar alertas já criados:

  • Pelo próprio tile: reabra Gerenciar alertas, selecione a seta ao lado do nome do alerta para editá-lo, ou a lixeira para excluí-lo.
  • Pelo menu de configurações: ícone de engrenagem > Configurações > aba Alertas, onde é possível ligar/desligar, editar ou excluir.
  • Nos aplicativos móveis do Power BI, diretamente no tile.

Adicionando imagens, vídeos e outros conteúdos

Além de fixar visuais de relatórios, um dashboard aceita tiles criados diretamente nele, sem depender de um relatório de origem: imagem, caixa de texto, vídeo, dados de streaming ou conteúdo web (código incorporado). Isso torna o dashboard mais informativo e visualmente atraente.

O caminho geral é o mesmo para qualquer tipo: selecione a seta ao lado de Editar no menu superior, escolha Adicionar um tile e selecione o tipo desejado.

Adicionar uma imagem ▸

Útil para exibir, por exemplo, a logomarca da empresa.

  1. Em Adicionar um tile, escolha Imagem > Avançar.
  2. Informe um título e subtítulo opcionais, a URL da imagem e, se quiser transformar o tile em hyperlink, marque Definir link personalizado.
  3. Selecione Aplicar e depois redimensione/posicione o tile no dashboard.
A imagem precisa estar hospedada em uma URL pública e acessível sem autenticação. Não é possível usar imagens do OneDrive ou SharePoint (exigem login), nem arquivos no formato .svg. Prefira um servidor web público, uma CDN ou um serviço de armazenamento em nuvem com acesso anônimo habilitado (por exemplo, Azure Blob Storage).
Adicionar uma caixa de texto ▸

Útil para criar títulos de seção dentro do dashboard (basta digitar o texto e aumentar o tamanho da fonte).

  1. Escolha Caixa de texto > Avançar.
  2. Preencha título/subtítulo opcionais e o conteúdo formatado do texto.
  3. Selecione Aplicar e ajuste o tamanho e a posição do tile.
Adicionar um vídeo ▸

Vídeos do YouTube ou Vimeo tocam diretamente dentro do tile no dashboard.

  1. Escolha Vídeo > Avançar.
  2. Informe a URL do vídeo e, opcionalmente, título/subtítulo com um link personalizado (por exemplo, para a playlist completa no YouTube).
  3. Selecione Aplicar, depois redimensione o tile; selecione o tile para reproduzir o vídeo.
Adicionar conteúdo web (código incorporado) ▸

Permite colar qualquer código HTML de incorporação (embed) como tile — por exemplo, um post do Twitter/X, um player de vídeo customizado ou conteúdo de sites como embed.ly.

  1. Escolha Conteúdo da Web > Avançar.
  2. Cole o código de incorporação (e, se quiser, título/subtítulo).
  3. Selecione Aplicar e ajuste o tamanho do tile.
Dicas práticas: use sempre https como origem do iframe (uma origem http resulta em tile em branco); para o player ocupar todo o espaço do tile ao redimensionar, defina width="100%" e height="100%" no código embutido, em vez de valores fixos em pixels.

Editando os detalhes de um tile

Depois de criado, qualquer tile pode ser reconfigurado:

  1. Passe o mouse sobre o canto superior direito do tile e selecione as reticências (...).
  2. Selecione Editar detalhes para abrir a janela de detalhes do tile.
  3. Altere o título, o subtítulo e, na seção de funcionalidade, defina um link personalizado — o destino pode ser uma página externa, outro dashboard ou relatório do mesmo workspace, ou um relatório SSRS. Por padrão, selecionar um tile leva ao relatório de origem (ou ao Q&A, se foi criado ali).
  4. Selecione Aplicar/Salvar para confirmar.

Outras ações disponíveis pelo mesmo menu de reticências:

  • Fixar tile: duplica o tile para outro dashboard, existente ou novo.
  • Excluir tile: remove o tile do dashboard, mas não apaga o visual original no relatório de onde ele veio.

Para trocar a visualização exibida em um tile já existente, não há edição direta: exclua o tile e adicione um novo a partir do visual desejado.

Boas práticas e temas de dashboard

Pense no público antes de desenhar

Um bom dashboard prioriza a informação mais importante de forma limpa e sem excessos. Antes de organizar os tiles, vale responder:

  • Como o público vai usar o dashboard no dia a dia?
  • Quais métricas realmente ajudam nas decisões?
  • Que suposições culturais ou de contexto podem influenciar as escolhas de design?
  • Do que exatamente esse público precisa para ter sucesso?

Lembre-se: o dashboard é uma visão geral, um ponto único para monitorar o estado atual dos dados — os detalhes ficam nos relatórios e modelos semânticos por trás dele. Só inclua um detalhe no dashboard se for algo que o público realmente precisa acompanhar de perto; o restante pode ser explorado via drill-through nos relatórios subjacentes.

Conte uma história em uma única tela

Como os dashboards existem para mostrar informação importante de relance, o ideal é caber tudo em uma única tela, evitando barras de rolagem. Se o layout está poluído, remova tudo que não for essencial. Ao apresentar um dashboard, use o modo de tela cheia, sem distrações.

Considere também onde o dashboard será exibido: em um monitor grande é possível incluir mais conteúdo, mas em tablets e celulares um dashboard mais enxuto, com menos tiles, é muito mais legível.

Destaque o que importa

Se textos e visualizações têm todos o mesmo tamanho, fica difícil para o leitor saber onde focar. Cartões (cards) com um número em destaque são uma ótima forma de realçar uma métrica importante — desde que venham acompanhados de contexto suficiente para serem interpretados corretamente.

A maioria das pessoas lê de cima para baixo e da esquerda para a direita. Por isso, posicione a informação de nível mais alto no canto superior esquerdo e vá aumentando o detalhe conforme o olhar se move na direção natural de leitura.

Use a visualização certa para os dados

Evite variedade só por variedade — cada visual deve ajudar a contar a história, não decorar a tela. Algumas recomendações práticas:

  • Evite visuais difíceis de ler, como gráficos 3D.
  • Gráficos de pizza, rosca e indicadores circulares raramente são a melhor escolha; gráficos de barras e colunas costumam facilitar mais a comparação de valores lado a lado.
  • Pizzas funcionam melhor com menos de oito categorias e para relações parte-todo, não para comparar partes entre si.
  • Gauges (indicadores) são ótimos para mostrar o status atual em relação a uma meta.
  • Mantenha consistência nas escalas dos eixos, na ordem das dimensões e nas cores usadas para os mesmos valores em diferentes gráficos.
  • Evite mais de três ou quatro dígitos ao exibir números — prefira formatos como "3,4 milhões" em vez de "3.400.000".
  • Não misture períodos de tempo diferentes no mesmo gráfico, nem escalas muito distintas (por exemplo, uma medida em milhões ao lado de outra em milhares) sem usar um eixo secundário.
  • Remova rótulos de dados desnecessários — muitas vezes o próprio gráfico de barras já comunica bem os valores.
  • Escolha a ordenação de acordo com o objetivo: por medida, para destacar o maior/menor valor; por eixo, quando o leitor precisa localizar rapidamente uma categoria específica entre várias.
Para aprofundar, vale estudar os princípios de Gestalt de percepção visual e consultar referências como Information Dashboard Design e Show Me the Numbers, de Stephen Few, Envisioning Information, de Edward Tufte, e Advanced Presentations by Design, de Andrew Abela.

Otimizando um dashboard para celulares

Por padrão, em modo retrato no celular os tiles de um dashboard aparecem um atrás do outro, todos do mesmo tamanho. No serviço Power BI, o dono do dashboard pode criar uma exibição personalizada especificamente para esse modo retrato — o chamado layout para celular.

  1. Abra o dashboard no serviço Power BI.
  2. Selecione a seta ao lado de Editar e escolha Layout para celular.
  3. Na tela de edição, arraste, redimensione ou desafixe tiles para montar a versão mobile. Os tiles desafixados vão para o painel de tiles não fixados, e ficam lá até serem adicionados de volta.
  4. Se quiser desfazer tudo, selecione Redefinir tiles para voltar ao estado anterior.
  5. Ao terminar, volte para a versão web selecionando Layout para web no menu superior.
O Power BI salva o layout para celular automaticamente e em tempo real: enquanto você edita, qualquer pessoa visualizando o dashboard pelo celular já vê as mudanças. Se você desafixar todos os tiles, o dashboard no celular ficará momentaneamente vazio. Além disso, ao girar o telefone para o modo paisagem, o layout exibido volta a ser o layout web padrão, não o layout para celular.

Criando um QR code para um tile

Um QR code conecta qualquer lugar do mundo físico diretamente a uma informação de BI, sem precisar navegar ou pesquisar — por exemplo, colado em um equipamento, em uma parede ou em um e-mail. Quem escaneia o código (e tem acesso ao dashboard) abre o tile direto no aplicativo móvel, em modo foco.

  1. Abra o dashboard no serviço Power BI.
  2. Nas reticências do tile desejado, escolha Abrir em modo foco.
  3. Em modo foco, nas reticências, selecione Gerar código QR.
  4. Baixe a imagem (gerada em formato JPG, com o mesmo nome do tile) para imprimir ou incluir em um documento/e-mail.

Para imprimir: baixe o arquivo, abra-o em um computador conectado a uma impressora, imprima em tamanho real (100%) e recorte o código para fixá-lo no local relevante.

Temas de dashboard

Os temas de dashboard permitem aplicar uma paleta de cores a todo o dashboard de uma vez — cores corporativas, sazonais ou qualquer outra combinação. Quando um tema é aplicado, todos os visuais do dashboard passam a usar as cores do tema selecionado (com algumas exceções). Alterar as cores dos visuais no dashboard não afeta o relatório de origem.

  1. Abra um dashboard que você possa editar e selecione Editar > Exibir > Tema.
  2. No painel de temas, escolha um dos temas prontos (por exemplo, Claro — o padrão — ou Escuro).
  3. Para personalizar, selecione Personalizado no menu suspenso e defina cores próprias; ao adicionar uma imagem de fundo, use resolução de pelo menos 1920x1080, hospedada em uma URL pública.
  4. Também é possível enviar um arquivo JSON de tema — o mesmo tipo de arquivo usado no Power BI Desktop para relatórios, ou obtido na Galeria de Temas da comunidade Power BI.
  5. Selecione Salvar para aplicar o tema a todos os tiles do dashboard.

Quando um relatório de origem já tem um tema próprio, ao fixar (pin) um tile você pode escolher entre Manter tema atual (preserva o tema do relatório, inclusive transparências) ou Usar tema do dashboard. Essa opção de "Tile Theming" só aparece quando o relatório foi criado no Power BI Desktop com um tema aplicado e depois publicado no serviço.

Limitações: temas de dashboard não se aplicam a páginas de relatório ao vivo fixadas, tiles de iframe, tiles SSRS, tiles de pasta de trabalho (workbook) ou imagens. Além disso, temas personalizados só podem ser criados no serviço Power BI (embora sejam visíveis também nos aplicativos móveis) e funcionam apenas em tiles fixados a partir de relatórios.

Introdução a metas e scorecards

O que são metas e scorecards

Metas (goals) são um recurso do Power BI para curar e acompanhar objetivos de negócio importantes em um único lugar, promovendo responsabilidade, alinhamento e visibilidade entre equipes. Antes de qualquer passo prático, é essencial entender três conceitos que se encaixam entre si:

Scorecard

É a "coleção": um painel que reúne várias metas relacionadas, para acompanhá-las ao longo do tempo em uma única visão.

Meta (goal)

É uma métrica individual dentro de um scorecard, com um valor atual e um alvo final (target), além de datas de início/fim e um status. Uma meta pode ter subgoals (submetas) associados a ela.

Meta manual x meta conectada

Uma meta manual tem seu valor atualizado à mão, por check-ins periódicos de uma pessoa responsável. Uma meta conectada busca o valor atual automaticamente de um relatório ou modelo semântico existente, atualizando-se sozinha conforme os dados são atualizados.

Resumindo a relação entre os três: um scorecard é composto por uma ou mais metas, e cada meta pode ser manual (valor digitado por alguém) ou conectada (valor puxado direto de um relatório/modelo semântico). É esse encadeamento — scorecard → meta → origem do valor — que estrutura todo o recurso.

Para criar um scorecard em um workspace específico, é preciso ter papel de Colaborador ou Proprietário nesse workspace, além de permissão de build sobre o modelo semântico envolvido.

O hub de Scorecards

Ao entrar no serviço Power BI, o item Scorecards no painel de navegação leva ao hub de scorecards. Ele é organizado em:

  • Recomendados: scorecards e metas mais relevantes para você, curados automaticamente com base em metas atribuídas a você, editadas por você ou com check-in recente. Uma meta só aparece aqui se tiver pelo menos valor atual e alvo final definidos.
  • Recentes, Favoritos, Compartilhados comigo, Todos os scorecards: abas de navegação para localizar rapidamente qualquer scorecard ao qual você tem acesso.

É possível alternar entre exibição em lista e exibição compacta (em pré-visualização), que se ajusta melhor a telas variadas e permite redimensionar colunas, mas não permite criar ou editar metas.

Criando um scorecard

  1. No serviço Power BI, selecione Métricas no painel de navegação para abrir o hub de métricas.
  2. Selecione Novo scorecard.
  3. Dê um nome ao scorecard selecionando o ícone de edição ao lado de "Untitled Scorecard".
  4. Por padrão, o scorecard é salvo no Meu Workspace; para movê-lo, use Arquivo > Mover scorecard e escolha o workspace de destino.

Ao mover o scorecard para um workspace, o Power BI salva ali tanto o scorecard quanto um modelo semântico próprio, criado automaticamente para armazenar os dados de todas as métricas.

Criando uma meta manual

  1. Dentro do scorecard, selecione Nova meta.
  2. Preencha os campos: nome da meta (único campo obrigatório), proprietários (pessoas ou grupos de distribuição), valor atual, alvo final, status (predefinido ou por regra), e datas de início e término.
  3. Selecione Salvar.

Se uma meta parecida já existe em outro scorecard, é possível vinculá-la em vez de duplicá-la. Também é possível criar até quatro níveis de submetas (subgoals) dentro de uma meta, cada uma podendo ser manual ou conectada.

Toda meta nova nasce com um ciclo de acompanhamento diário (o progresso é calculado dia a dia). Para mudar essa cadência, abra o scorecard, passe o mouse sobre a meta, escolha Mais opções > Ver detalhes > aba Período de tempo e ajuste a preferência. Isso altera apenas a tendência exibida, não a frequência real de atualização dos dados.

Criando metas conectadas

Em vez de digitar valores manualmente, é possível conectar o valor atual, o alvo final, ou ambos, a um ponto de dado real de um relatório do Power BI já existente. A partir daí, o valor passa a ser atualizado automaticamente sempre que o modelo semântico subjacente for atualizado.

  1. Ao criar ou editar uma meta, no campo de valor atual (ou alvo final), selecione Conectar a dados.
  2. Pesquise e selecione o relatório desejado entre todos os que você tem acesso, em qualquer workspace.
  3. Navegue até o visual que contém o dado a acompanhar e selecione o ponto de dado ou o visual — o Power BI mostra um cartão resumindo a medida e os filtros aplicados.
  4. Selecione Conectar e depois Salvar.

É possível conectar a diferentes níveis dentro de um visual, e o cálculo varia conforme o nível escolhido:

  • Visual: Power BI calcula a medida no nível agregado.
  • Legenda: filtra a medida pelo item de legenda selecionado.
  • Ponto de dado: filtra pelo ponto de dado específico.
  • Valor do eixo: filtra pela categoria selecionada no eixo.

Quando o eixo do visual é um campo de data/hora (série temporal), o Power BI calcula a medida no último ponto da série e também traz o histórico — mas isso só funciona se a data for completa (dia, mês e ano); datas parciais, como "dia da semana" ou "mês", não geram histórico.

Algumas limitações atuais: em gráfico de barras/colunas 100% empilhado, o Power BI usa o valor da medida, não o percentual; em cartão multilinha e em tabelas com mais de uma coluna de medida, é usada apenas a primeira medida; em gauges e KPIs, apenas o valor é conectado (não o alvo, mínimo ou máximo); Multi-Geo não é suportado; e valores conectados via DirectQuery/Live a um datamart não se atualizam automaticamente.

Por que uma meta pode não estar atualizando

  • Metas manuais nunca se atualizam sozinhas — dependem de check-ins regulares de quem é responsável por elas.
  • Sem atualização agendada: o valor de uma meta conectada só muda quando o modelo semântico é atualizado; sem uma atualização agendada configurada, o valor fica parado.
  • Modelos semânticos push não atualizam metas automaticamente.

De modo geral, metas conectadas só mudam na mesma frequência em que os dados do modelo semântico são atualizados (via importação, conexão direta ou DirectQuery), e o Power BI tira um retrato (snapshot) dos valores no máximo uma vez por dia, sempre retendo o último valor do dia.

Compartilhando um scorecard

A forma mais simples de dar acesso a um scorecard é usar o botão Compartilhar na barra de ações do scorecard, escolhendo se quem recebe pode recompartilhar e se pode acessar o modelo semântico subjacente. Também é possível configurar permissões no nível de cada meta individualmente, restringindo quais metas cada pessoa pode ver ou em quais pode fazer check-in — mesmo que ela tenha acesso de visualização ou build ao workspace como um todo.

Outras limitações importantes: metas não suportam BYOK (bring your own key) nem segurança em nível de linha (RLS); não há suporte a publicar na web, a compartilhamento entre tenants (B2B), a capacidades Multi-Geo, nem a cenários de embedded analytics; e o visual de scorecard não funciona em incorporação via SharePoint.

Usar o Power Automate para atualizar metas automaticamente

Monitorar scorecards manualmente consome tempo e está sujeito a erros. O Power BI permite acionar fluxos do Power Automate diretamente a partir de um scorecard, ajudando sua organização a reagir mais rápido a mudanças e a manter todos atualizados.

  1. Na página do hub de Scorecards, selecione o scorecard desejado.
  2. Selecione o botão Criar um fluxo na faixa de opções. O Power Automate abre a página do conector do Power BI.
  3. Escolha um gatilho (trigger) para iniciar o fluxo.
  4. Personalize as ações e condições do fluxo conforme o processo de negócio.

O Power Automate oferece ações e gatilhos próprios do Power BI para automatizar processos ligados a scorecards. Para saber o que cada ação ou gatilho faz, use o ícone de informação ao lado do item e selecione Saiba mais.

💡
O Power Automate também pode ser usado para disparar atualizações de metas a partir de eventos como atualização de um conjunto de dados, mudanças de status ou novos check-ins.

Atualizar metas e scorecards automaticamente

Metas conectadas a um modelo semântico ou a um visual de relatório podem ser atualizadas automaticamente sempre que os dados subjacentes forem atualizados. Ainda assim, problemas de configuração ou de tempo podem impedir que a meta reflita o dado mais recente.

SituaçãoO que fazer

Atualização manual necessáriaÉ possível forçar uma atualização pela interface do scorecard, mas isso nem sempre resolve dados desatualizados.
Atualizar várias metas de uma vezUse o script em PowerShell disponibilizado pela comunidade Power BI para atualizar todas as metas de um workspace.

⚠
Boas práticas: garanta que os modelos semânticos sejam atualizados antes de disparar a atualização das metas, utilize entidades de serviço (service principals) ou identidades gerenciadas para scripts de automação, e monitore os logs de atualização para identificar falhas.

Criar submetas

Submetas agrupam metas relacionadas sob uma meta "pai", que pode ser expandida ou recolhida, deixando o scorecard mais organizado e fácil de ler. As submetas podem ser valores independentes do pai ou podem fazer rollup (consolidação automática) para o valor da meta pai.

💡
Se o objetivo é exibir a mesma meta em vários scorecards sem duplicá-la, use metas vinculadas em vez de submetas (veja a página 8).
  1. Abra um scorecard.
  2. Selecione a meta desejada e escolha Novo > Adicionar submeta, ou passe o mouse sobre a meta e use Mais opções (...) > Nova submeta.
  3. Repita o processo para criar quantas submetas forem necessárias.

Submetas podem ser manuais ou conectadas, da mesma forma que suas metas pai.

Submetas de rollup

Rollups consolidam automaticamente os valores das submetas em um valor de meta pai, recalculando sempre que os valores das submetas mudam e preservando o histórico. Funcionam tanto com submetas manuais quanto conectadas.

  1. Selecione o ícone de lápis para editar a meta pai.
  2. Ao lado dos campos Valor atual e Meta final, selecione Usar submetas.
  3. Escolha o tipo de agregação: SOMA, MÉDIA, MÍNIMO ou MÁXIMO.

É possível definir agregações diferentes para o valor atual e para a meta final, o que dá bastante flexibilidade ao modelo.

⚠
Atenção ao histórico: se quem cria o rollup não for o proprietário da conexão da meta, o histórico de dados conectados é apagado. Para preservar o histórico, o criador do rollup deve ser a mesma pessoa que é proprietária da conexão da meta. Rollups também sempre mostram o mesmo valor agregado para todos os usuários, independentemente das permissões de nível de meta que cada um tenha.

Criar regras automatizadas de status

Em vez de atualizar o status de uma meta manualmente, é possível definir regras que mudam o status com base em valor, percentual da meta atingido, condições de data, ou uma combinação desses fatores.

Para metas conectadas, as regras de status são reavaliadas a cada atualização dos dados do scorecard. Para metas manuais, são reavaliadas a cada novo check-in.
  1. No modo de edição do scorecard, selecione Mais opções (...) > Ver detalhes ao lado da métrica.
  2. Na guia Regras de status, selecione Nova regra.
  3. Escolha se a regra será baseada em Valor ou em Data.
  4. Selecione o qualificador (por exemplo, maior que, igual a, antes de, depois de).
  5. Informe o valor, o percentual da meta atingido, ou a data de referência, dependendo da escolha anterior.
  6. Defina o status exibido quando a regra for atendida e o status Caso contrário.

Você pode criar múltiplas condições e arrastar as regras para reordenar a prioridade entre elas.

⚠
Na experiência mobile, a atualização automática das regras de status ainda não é suportada.

Personalizar status do scorecard

Quando os status padrão do Power BI não refletem a terminologia da sua organização, é possível personalizá-los totalmente — criar novos, renomear, mudar cores e reordenar por prioridade.

No modo de edição do scorecard, acesse Gerenciar status pelo ícone de engrenagem, pela seção Status do painel de configurações, ou editando uma métrica inline.

  • Adicionar: use o botão Adicionar status no topo da lista.
  • Renomear: selecione o texto do status e digite o novo nome.
  • Mudar cor: use o seletor de cor ao lado do status.
  • Excluir: selecione o ícone de lixeira.
  • Reordenar: use as setas ou arraste o status para a posição desejada — a ordem define a prioridade usada para ordenar metas por status.
  • Restaurar padrão: selecione Redefinir status no topo da lista.
💡
Ao excluir um status, ele deixa de aparecer como opção em novos check-ins, mas o Power BI preserva o histórico de status excluídos (até 12) tanto no modelo semântico quanto no histórico de check-ins.
⚠
O Power Automate não oferece suporte a status personalizados de metas.

Ficar por dentro das suas metas

É possível filtrar o scorecard pelos cartões de resumo no topo (por exemplo, metas "em risco" ou "atrasadas") ou usar a busca por palavra-chave para localizar rapidamente uma meta específica, sem perder o contexto das relações entre metas pai e filhas.

  1. No scorecard, selecione o nome da meta.
  2. No painel de detalhes, selecione Novo check-in.
  3. Escolha uma data, informe um valor novo ou atualizado, selecione um status e, opcionalmente, inclua uma nota.
  4. Selecione Salvar. O check-in aparece na seção Atividade do painel de detalhes.
  1. No scorecard, selecione o nome da meta e depois Novo check-in.
  2. Escolha uma data — o valor daquele dia é preenchido automaticamente e não pode ser sobrescrito.
  3. Selecione um status, inclua uma nota opcional e selecione Salvar.

Seguir metas

Use a função Seguir para acompanhar rapidamente as metas de seu interesse, mesmo navegando por scorecards diferentes. Todas as metas seguidas ficam reunidas no hub de Métricas, em Seguindo.

💡
Ao seguir uma meta, você recebe notificações do Teams sempre que a definição da meta é atualizada — por exemplo, um novo check-in ou uma mudança de status disparada por regra automatizada. Para parar de receber notificações, use a opção Deixar de seguir.

Criar assinaturas por e-mail

As assinaturas enviam atualizações periódicas por e-mail sobre um scorecard, mantendo você e sua equipe informados sem precisar acessar o Power BI.

  1. Abra o scorecard e selecione Assinar scorecard na faixa de opções.
  2. Selecione Adicionar nova assinatura.
  3. Defina nome, assunto e mensagem do e-mail.
  4. Escolha a frequência: por hora, diária, semanal ou mensal.
  5. Configure o horário (hora cheia, 15, 30 ou 45 minutos, AM/PM e fuso horário).
  6. Defina a data de início e, opcionalmente, a data de término.
  7. Opcionalmente, inclua um link para o scorecard com permissão de visualização para os destinatários.
  8. Selecione Salvar e fechar.

O e-mail traz uma tabela com até 50 metas, mostrando nome, status, valores e data de vencimento. Assinaturas podem ser editadas, ativadas/desativadas ou excluídas a qualquer momento em Gerenciar todas as assinaturas.

Permissões em nível de meta

Em muitas organizações, nem todo mundo deve ver ou editar as mesmas metas — por exemplo, apenas gestores devem enxergar metas de RH e financeiro, enquanto metas operacionais podem ficar visíveis a todos. As permissões em nível de meta resolvem esse cenário.

  1. No hub de Métricas, selecione o scorecard e depois o ícone de edição (lápis).
  2. Selecione o ícone de engrenagem para abrir o painel de configurações do scorecard.
  3. Selecione a guia Permissões.
  4. Selecione Adicionar função ou Mais opções (...) em uma função existente para abrir as configurações de papel.

Cada função pode combinar os seguintes tipos de permissão:

  • Visualização: concede acesso para ver metas específicas do scorecard.
  • Atualização: concede acesso para fazer check-in em aspectos específicos de uma meta — Nota (adicionar notas), Status (atualizar status) e Atual (atualizar o valor atual), em qualquer combinação.
  • Aplicar a todos: propaga a permissão para todas as submetas existentes e futuras daquela meta.
💡
É possível definir uma função como padrão, aplicada a qualquer pessoa que acesse o scorecard e não pertença a outra função específica. Quem pertence a uma função específica assume as permissões dessa função em vez das padrão.
⚠
As funções de permissão (exceto a padrão) também se aplicam ao modelo semântico gerado pelo scorecard. Permissões em nível de meta são diferentes das permissões de edição do workspace: para dar acesso total de edição ao scorecard, use os papéis de Contribuidor ou Membro no workspace. O suporte completo a segurança em nível de linha (RLS) automática baseada em permissões de meta ainda não está disponível.

Depois de configurar as funções, compartilhe o scorecard pelo botão Compartilhar, escolhendo Pessoas específicas podem ver e compartilhar para personalizar quem recebe acesso.

Organizar colunas, metas e scorecards

Como autor de um scorecard, você pode renomear, ocultar ou reordenar colunas, reordenar metas (inclusive transformando uma meta em submeta de outra) e mover ou copiar o scorecard inteiro para outro workspace.

Selecione uma meta e arraste-a para cima ou para baixo. Recuando levemente a meta, ela se torna submeta da meta acima — e passa a herdar a cor da meta pai.

  • No modo de edição, selecione a seta ao lado da coluna > Configurações da coluna > Mover para a direita/esquerda ou Ocultar esta coluna.
  • Para reexibir colunas ocultas, use Mostrar/Ocultar colunas e, em Editar colunas de exibição, marque a coluna desejada, arraste para reordenar, ou selecione Redefinir para o padrão.
  • Para renomear, selecione a coluna em Configurações da coluna e digite o novo nome (entre 1 e 25 caracteres).

Mover ou copiar um scorecard

Útil para reutilizar um scorecard modelo entre departamentos, testar um scorecard em "Meu workspace" antes de publicá-lo, ou reaproveitar a definição de metas de um scorecard existente.

  1. No menu Arquivo, selecione Mover scorecard ou Copiar scorecard.
  2. Escolha o workspace de destino na lista e selecione Continuar.
💡
Ao copiar um scorecard, você escolhe se quer incluir ou não o histórico de check-ins — útil para reaproveitar o mesmo modelo em um novo período fiscal.

Criar metas vinculadas (preview)

Metas vinculadas permitem exibir a mesma meta em vários scorecards, em workspaces diferentes, sem duplicar dados. Check-ins, edições e atualizações aparecem em todos os locais onde a meta está vinculada. É o recurso ideal, por exemplo, quando a liderança tem um scorecard corporativo e cada departamento reutiliza algumas dessas metas no próprio scorecard, somando outras específicas da área.

  1. Abra um scorecard e selecione Editar.
  2. Selecione o botão Novo.
  3. Selecione Vincular a meta existente (preview).
  4. Escolha o scorecard de origem e selecione as metas que deseja incluir.
  5. Selecione Continuar. As metas vinculadas aparecem no scorecard atual.

Só é possível editar a meta a partir da origem (é possível navegar até ela pelo menu de opções da meta vinculada, em Ir para a meta de origem); check-ins podem ser feitos direto na meta vinculada, desde que você tenha permissão na origem, e refletem em todos os scorecards que a utilizam.

⚠
Considerações: ao vincular várias metas de uma vez, a ordem e as relações pai/filha da origem são preservadas. Metas vinculadas não são filtradas por hierarquia (mantêm seu valor original) e não é possível fazer check-in nelas em uma visão hierárquica filha. Se uma meta de rollup for vinculada a outro scorecard, ela continua mostrando o valor calculado na origem, ignorando submetas do scorecard de destino.

Introdução às hierarquias em scorecards

As métricas do Power BI oferecem suporte a scorecards em cascata, que fazem rollup ao longo de hierarquias configuradas no próprio scorecard. Você define uma hierarquia e mapeia os modelos semânticos usados pelas metas para os níveis da hierarquia e para os campos de proprietário, criando automaticamente uma visão de scorecard para cada "fatia" dos dados.

Pré-requisitos

  • Workspace em capacidade Premium ou Premium por Usuário (PPU).
  • Permissão de edição no scorecard.
  • Pelo menos uma meta conectada no scorecard.
  • Acesso de build (compilação) aos modelos semânticos conectados ao scorecard.

Depois de configurada, a hierarquia faz o Power BI propagar as metas conectadas para cada nível: os usuários podem navegar (drill) pela hierarquia para ver progresso, status e realizar check-ins em diferentes níveis, com valores, status e proprietários mudando conforme o nível selecionado.

  1. No modo de edição do scorecard, selecione Configurar uma hierarquia no menu Novo (ou Gerenciar hierarquias no slicer Todos).
  2. Dê um nome à hierarquia e construa os níveis desejados.
  3. Mapeie cada nível para os campos correspondentes nos modelos semânticos conectados às métricas do scorecard, desmarcando campos que não devem entrar no mapeamento.
  4. Opcionalmente, mapeie proprietários por nível de hierarquia (a coluna de proprietário passa a mudar dinamicamente conforme a fatia de dados exibida).
  5. Salve a hierarquia para ver os valores e proprietários conectados mudarem dinamicamente.

É possível criar múltiplas hierarquias para cruzar diferentes fatias dos dados — por exemplo, uma hierarquia de geografia e outra de produto, permitindo visualizar métricas como "notebooks na Alemanha" usando o slicer.

💡
Metas manuais (sem conexão a dados) também aparecem nos scorecards filhos, mas exibem valores manuais em branco — ainda assim podem receber check-in e ser atualizadas na visão do scorecard filho.

Metadados da métrica: nome, proprietários, status e datas de início/vencimentoDados de check-in: notas, status (quando aplicável) e valores (quando aplicável)
Conexões de dados, regras de status e configurações de acompanhamento—
⚠
Limites e considerações: até 10.000 itens por hierarquia (somando todos os modelos semânticos), até cinco hierarquias e até cinco níveis por hierarquia. RLS estática e dinâmica é suportada, mas roteada pelo criador da hierarquia — todos os visualizadores do scorecard "assumem" o acesso desse criador. Rollups ainda não são suportados em scorecards filhos, e reutilizar hierarquias entre scorecards também não é possível: cada scorecard precisa da própria hierarquia.

Cenários de uso de hierarquias

Scorecards em cascata são especialmente úteis para padronizar metas entre diferentes segmentos de uma organização em grande escala. Três cenários ilustram bem o valor do recurso.

Saúde organizacional entre equipes

Acompanhe engajamento, satisfação e metas de contratação mapeadas por divisão. A liderança sênior enxerga como cada divisão está performando em relação a metas padrão, como taxa de rotatividade, treinamentos de compliance e diversidade nas contratações — tornando o scorecard uma ferramenta de decisão em alto nível.

Métricas de varejo por local e produto

Combine uma hierarquia de geografia com uma hierarquia de produto para cruzar as duas dimensões — por exemplo, métricas de notebooks na Alemanha, ou de um modelo específico em Berlim. Proprietários podem ser mapeados por local, garantindo que cada gerente de filial seja responsável pelas metas da própria unidade.

Hierarquias organizacionais

Use a própria hierarquia organizacional como hierarquia do scorecard, útil sobretudo para métricas de compliance que cada equipe precisa atingir. A liderança consegue ver rapidamente números consolidados e detalhar por equipe para identificar quem está bem e quem está atrasado, com apoio da visão de heatmap para comparação lado a lado.

Visualizar hierarquias no scorecard

Existem duas formas de visualizar e interagir com uma hierarquia dentro de um scorecard.

Use o slicer para navegar até o nível de hierarquia desejado. A partir daí, você pode abrir o painel de detalhes, ir até um relatório e fazer check-ins normalmente, como em qualquer outro scorecard. Valores conectados, proprietários mapeados e status definidos por regras refletem os dados corretos em cada nível, desde que existam relacionamentos entre os campos da hierarquia nos modelos semânticos subjacentes. Metas manuais aparecem com um ícone de informação indicando quais valores são manuais.

Também é possível visualizar interseções entre hierarquias diferentes (por exemplo, uma seleção de produto cruzada com uma seleção de geografia); o cabeçalho do scorecard mostra os dois níveis escolhidos.

Ao selecionar Heatmap nas opções de visão, você monta uma comparação lado a lado entre diferentes níveis da hierarquia — ótima para reuniões de acompanhamento de negócio. Essa experiência fica disponível também em modo de leitura, permitindo que consumidores explorem por conta própria. É possível personalizar quais informações aparecem em cada bloco de meta pelas configurações de exibição, acessadas pelo menu do slicer.

⚠
Limitações: requer workspace Premium ou PPU; os mesmos limites de itens, hierarquias e níveis descritos acima se aplicam. Permissões não podem ser definidas por nível de hierarquia — as permissões de nível de meta são as do scorecard original e valem para todos os níveis. O histórico não é suportado em metas hierárquicas (os dados são sempre consultados ao vivo no modelo semântico). Salvar e compartilhar visões de heatmap ainda não é suportado, e há um limite de uma seleção por hierarquia ao visualizar um scorecard hierárquico.
